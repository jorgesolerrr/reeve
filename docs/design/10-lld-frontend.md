## Purpose & scope

This document fixes the frontend's load-bearing structure: the state layer, the invalidation client, the viewer/editor per format, the HTML sandbox mechanics (NFR-2), the terminal registry, the Review tab's UX contract, the test approach, and styling. It settles what 05 left open ("interiors are prototype, settled by #17") — but it settles *structure*, not pixels: component composition and visual detail inside the feature folders remain prototype territory during implementation. What this document fixes may not be departed from without amending it.

## Module map

`app/src/` final layout — `lib/` is still the only module that talks to the backend (05):

| Module | Owns |
|---|---|
| `lib/bridge.ts` | The Tauri `invoke`/`listen` wrapper: envelope unwrapping (03's single error shape), typed by `generated/types.ts`. **The single mock point for tests.** |
| `lib/queries.ts` | Query-key derivation and the TanStack Query hooks, one per API operation. |
| `lib/events.ts` | The one global event subscription: the four-event → invalidation mapping. |
| `lib/terminal-registry.ts` | xterm.js instances owned outside React, keyed by ticket. |
| `lib/store.ts` | The single zustand store: navigation + pure UI state. |
| `components/ui/` | shadcn/ui components, generated by its CLI — repo-owned code, freely editable. |
| `board/ node/ workspace/ settings/ preflight/` | The five surface folders (05) — interiors prototype territory. |

## State layer: one query cache + one store, and nothing else

- **TanStack Query** holds all server state — every read from the core. This ratifies what the reference research already settled: both reference apps converge on it, and the HLD's "thin query cache keyed by operation + args, invalidated by scoped events" is a textbook `invalidateQueries` setup.
- **One zustand store** holds all pure UI state: active project, navigation, per-launch Context Package adjustments, open-tab state. The core holds no session state (03); neither does anything else in the frontend.
- **The ceiling is law:** one query cache + one UI store. No MobX, no third reactive system, no client-side mirror of server data. Emdash ran three sources of truth for "current state of task X" and needed a file literally named `reset-stale-acp-agent-statuses.ts` to reconcile them — that file is the argument.

### Navigation: state, not a router

No router library. Navigation is a slice of the zustand store:

```ts
{ surface: 'board' | 'node' | 'workspace' | 'settings' | 'preflight',
  nodeId?: NodeId, ticketId?: TicketId, workspaceTab?: 'terminal' | 'review' }
```

The user never sees a URL in a Tauri webview, deep links buy nothing in v1, and reeve's UX is a constant Board ↔ Workspace ↔ Node ping-pong whose state (which tab, which Context Package tweaks) already lives in the store — splitting it between a router and zustand would be exactly the two-reactive-systems sin. If history is ever wanted, it is a `back()` stack in the same store.

## Query keys and the invalidation client

Canonical key shape: **`[projectPath, area, ...detail]`**. Project first — 03 makes `project` explicit on every operation, and switching projects must never cross caches. Area second, so invalidation can strike by prefix.

| Query | Key |
|---|---|
| Board | `[proj, 'graph', 'board']` |
| Node (body + front-matter + link table) | `[proj, 'graph', 'node', nodeId]` |
| Backlinks | `[proj, 'graph', 'backlinks', nodeId]` |
| Search / graph listings | `[proj, 'graph', ...]` |
| Workspace status, diff, verify | `[proj, 'ws', ticketId, ...]` |
| Runs of a ticket | `[proj, 'ws', ticketId, 'runs']` |
| Project config / agent profiles / preflight | `[proj, 'config', ...]` / `['machine', ...]` |

`lib/events.ts` subscribes **once at app start** — never per component — and translates the four events (03's closed catalog):

- **`graph_changed { paths }`** — two strikes. *Exact:* derive `nodeId` from each path (filename = id, 02's rule) and invalidate `[proj, 'graph', 'node', id]`. *Coarse:* invalidate every other `[proj, 'graph']` query by prefix. The coarse strike is honesty, not laziness: editing file A changes file B's backlinks — the path→affected-query relation is not 1:1, and pretending precision there is self-deception. Board and backlinks are cheap re-queries (NFR-1), and TanStack Query only refetches queries with mounted observers — off-screen queries just go stale-marked.
- **`workspace_changed { ticketId }`** → invalidate `[proj, 'ws', ticketId]` by prefix + `[proj, 'graph', 'board']`.
- **`run_exited { ticketId, runKind, exitCode }`** → invalidate `[proj, 'ws', ticketId]`, and hand `exitCode` straight to the UI — the review prompt (agent) and the pass/fail signal (verify) must not wait for a re-query (03's one extra datum).
- **`pty_output`** → **never touches TanStack Query.** Routed directly to the terminal registry — the HLD's declared exception stays an exception in the client too.

## Viewers and editors by format

### Markdown: CodeMirror 6 source + markdown-it preview

A domain constraint rules before taste: **`save_doc` writes verbatim** (03), front-matter carries unknown keys that must survive (06), and Sources own materialized regions with fixed markers (09). WYSIWYG editors (Milkdown/TipTap) round-trip through ProseMirror and *normalize* Markdown on save — silent reformatting of bytes that are not theirs. Disqualified outright.

- **Editing:** CodeMirror 6 in source mode (what Obsidian builds on). Wiki-links become clickable via CM decorations (Ctrl+click navigates); soft wrap and Markdown ergonomics on. Lazy-loaded.
- **Preview:** markdown-it, fed by the **link resolution table the core already returns** with the node (03: core resolves, UI renders). Zero duplicated resolution logic; preview wiki-links navigate with the same table. Source/preview is a toggle — no Obsidian-style live-preview hybrid, which is a project in itself.
- **Saving:** explicit — dirty indicator + Ctrl+S → `save_doc` verbatim. Content authorship is the user's commit (02); a save is an act, not a drip.
- **Tickets:** an open Ticket is this surface with its front-matter *presented* (02) — a header panel above the editor; its exact form is prototype territory.

### Excalidraw: official package, explicit save

`@excalidraw/excalidraw` mounted in the Node surface for `.excalidraw` files (FR-2.2: view, edit, create). Lazy-loaded. **Assets — fonts included — ship in the bundle; no CDN** (NFR-5 offline-first): the asset path is configured explicitly, because this is the kind of detail that breaks silently without a network.

Save is **explicit**, same gesture as Markdown, despite Excalidraw's continuous `onChange`: consistency across editors, no watcher echo (each write fires `graph_changed` on the open file — autosave would invalidate the editor's own query dozens of times a minute and fight its own live canvas), and the domain's save-is-an-act stance. The file is wholly Excalidraw's JSON — native serialization through `save_doc` is safe verbatim. Escape valve on record: if explicit save proves unbearable under dogfooding, long-debounce autosave is a local change that touches no design.

### HTML: sandboxed iframe with an injected CSP (NFR-2)

Agent-generated HTML is untrusted input by definition (01). View-only, no filesystem access, no app APIs. Mechanics:

- Content arrives through the normal API (`get_node`) and mounts in an **`<iframe sandbox="allow-scripts">`** via `srcdoc` — **without** `allow-same-origin`, so the document runs in an *opaque origin*: no Tauri IPC, no storage, no parent access. Inline scripts do run — reeve's own design docs are interactive HTML; killing their JS would kill the format.
- The content is prefixed with `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:">`. The trick that makes this valid: **an applied CSP cannot be relaxed by the document itself** — a hostile meta CSP only combines, and the strictest policy wins. `default-src 'none'` also **blocks the network**: no exfiltration via `fetch` or remote `<img>`.
- Assumed limit: **self-contained HTML only** — relative sibling assets do not resolve. That is the dominant real case (the atlas, agent-emitted reports). The upgrade path if multi-file docs ever matter: a custom Tauri protocol (`reeve-doc://`) serving containment-checked siblings with CSP headers — documented, not built. Chosen over that protocol for v1 because it adds zero new Rust surface and no containment check to audit (the lesson of emdash's broken `../`-vs-`..\` guard).

### Diff: Monaco, lazy, read-only in v1

Monaco's diff editor, loaded by dynamic import only when the Review tab opens — the Board never pays for it; bundle weight in a desktop app is a one-time startup cost, not a network cost. Side-by-side default with an inline toggle; per-file models prefetched through a model registry (emdash's pattern, lifted near-verbatim). Read-only in v1: ADR-0005 defers inline diff→agent comments to the post-v1 loop model, so the comment machinery — the reason Monaco wins over lighter viewers — is **designed-for, not shipped**: named here as the planned extension, designed in the loop model when it lands.

## The terminal registry

`lib/terminal-registry.ts` — a module outside the React tree (sibling of the store), owning xterm.js wholesale:

- **Map `ticketId → { Terminal, FitAddon, owned DOM element, mountCount }`.** Keyed by ticket, not by run: 08 enforces one live Run per ticket (the `Starting` reservation), and the terminal *is* that slot's view.
- **The instance outlives the component.** The registry owns a detached `<div>`; the Workspace surface adopts it on mount and releases it on unmount (mount-count). Switching tabs or surfaces never kills or clears a terminal — scrollback lives in the xterm buffer, not in React. This is the emdash pattern the research flagged for near-verbatim adoption, and the defect it prevents is the reason.
- **`pty_output` writes direct:** `lib/events.ts` routes `{ ticketId, data }` → `registry.get(ticketId).write(data)`, bypassing the query cache.
- **Cold attach** (app restarted; a Run alive from a previous session or freshly dead): seed the buffer from `read_run_log` — the bounded 2 MiB tail 08 added exactly for this — then attach the live stream.
- **Input and size:** `term.onData` → `write_stdin`; FitAddon + `term.onResize` → `resize_pty`, honoring 08's documented handshake (spawn at 80×24, frontend resizes as soon as xterm mounts). Web-links addon on — agents print URLs.
- **Buffer lifecycle:** survives `run_exited` — reading the scrollback after the agent dies is precisely the review flow — and is disposed only when the Workspace is destroyed (merge/discard) or the app closes.

## The Review tab

ADR-0004 rules here: write-back rides the diff, **merge is the approval**. The Resolution Note (`.reeve/notes/T-<n>.md`, 06) is the transcript thesis realized — if it renders as just another file in the diff list, the memory loop is buried under code changes. First-class means structure:

1. **Verdict header** (pinned): verify signal (pass/fail chip from the last verify Run's `exitCode` + re-verify button), link warnings (warn, never block — FR-5.3), and the three endings — **Merge** primary, Push, Discard (destructive, confirmed). For imported Tickets, Merge chains the offer-to-close dialog (09's trigger contract, implemented here).
2. **Resolution Note panel**, pinned below the header: the note **rendered** (markdown-it, navigable wiki-links), not raw diff — it is the agent's account of what it did and why; it is *read*, not line-inspected. If the Run left no note: a visible warning ("this run wrote no Resolution Note") — an absent note is a hole in the memory and deserves friction.
3. **File list + Monaco diff**, partitioned into two groups: **Memory** (`.reeve/`: the note, touched docs) and **Code** (everything else) — the work↔memory loop made visible in the review itself. The note appears here too, collapsed by default (redundant with the panel), so the diff remains the complete inventory of what lands.

Settled without a prototype ticket: the parts are known components (chips, a rendered panel, list + Monaco), fidelity risk is low, and feature-folder interiors are prototype territory during implementation anyway.

## Tests

The architecture dictates what deserves testing: nearly all frontend logic with real risk lives in `lib/` — surfaces mostly render data the core already derived (the board is not computed client-side).

1. **Vitest on `lib/`** — the bulk. Pure Node, no DOM: "a `graph_changed` with `paths: ['docs/a.md']` invalidates exactly these keys"; "a registry entry at mountCount 0 keeps its buffer"; "cold attach seeds from the log before attaching the stream". **Mocking happens at `lib/bridge.ts`, one point**, with responses typed by `generated/types.ts` — ts-rs guards the contract, so the mock cannot drift silently. This is where the curated boundary pays for its existence.
2. **Testing Library, surgical** — only components with their own conditional logic: the Review verdict header (which endings are offered, the absent-note warning), the offer-to-close dialog. Whole surfaces are not component-tested.
3. **No E2E in v1.** `tauri-driver` on CI — and on Windows, the Tier 1 leg — is purchased fragility; preflight (FR-4.4) and daily dogfooding cover the smoke. On record as the post-v1 addition if regressions demand it.

**CI amendment to 05:** step 5 becomes `pnpm install && pnpm -C app test && pnpm -C app build` — the skeleton's "strict TS compile is the frontend's test until #17 adds real ones" debt is hereby paid.

## Styling

**Tailwind v4 + shadcn/ui, used directly**: components generated by the shadcn CLI into `app/src/components/ui/` — repo-owned code (Radix underneath for accessible primitives; Review and Board are full of dialogs, menus, tooltips), no external design system adopted. Discipline: shared primitives live in `components/ui/`; feature-folder interiors stay free (05).

## Deliberately not designed here

- **Inline diff→agent comments** — the loop/hook model's (ADR-0005); Monaco is the prepared seat, not the design.
- **Live-preview hybrid Markdown editing** — source/preview toggle in v1.
- **Multi-file HTML docs** — the `reeve-doc://` protocol sketch above is the named upgrade path, unbuilt.
- **E2E harness** — post-v1, if dogfooding's regressions demand it.
